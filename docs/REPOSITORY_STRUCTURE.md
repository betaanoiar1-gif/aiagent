# Repository Structure Rationale

```
aiagent/
├── research/
│   ├── hypotheses/             # Tracked hypotheses (HYP-xxxxxx manifests)
│   ├── experiments/            # Isolated experiment directories (EXP-xxxxxx)
│   │   └── registry.json       # Central index of all recorded experiments
│   ├── benchmarks/             # Benchmark workload definitions
│   ├── reports/                # Cross-experiment comparisons & synthesis
│   ├── datasets/               # Dataset manifests and split definitions
│   └── prompts/                # Reference prompt test suites
├── runtime/
│   ├── profiler/               # Hardware and software discovery engines
│   │   ├── hardware.py         # HardwareProfiler (CPU, RAM, GPU, Disk, OS)
│   │   └── software.py         # SoftwareProfiler (Python, Kernel, Git, Packages)
│   ├── measurement/            # Resource telemetry layer
│   │   ├── monitor.py          # Concurrent background resource monitor
│   │   └── metrics.py          # Telemetry dataclasses and aggregations
│   ├── runner/                 # Experiment execution orchestration
│   │   ├── runner.py           # BenchmarkRunner (manages full lifecycle)
│   │   └── reproducibility.py  # Replication and comparative validation
│   ├── config/                 # Schemas and configuration loaders
│   │   ├── experiment_config.py# Pure scientific parameters
│   │   ├── runtime_config.py   # Pure runner execution settings
│   │   └── schema.py           # Unified ExperimentRecord & Enums
│   └── registry/
│       └── registry.py         # Central experiment indexing and persistence
├── engines/                    # Compute engine abstractions
│   ├── base.py                 # BaseEngine abstract class
│   └── mock_engine.py          # DeterministicSyntheticEngine for Phase 0
├── models/                     # Model architecture abstractions
│   ├── base.py                 # BaseModel abstract class
│   └── mock_model.py           # SyntheticBenchmarkModel for Phase 0
├── evaluation/                 # Metrics, comparison, and reporting
│   ├── reporter.py             # Markdown and JSON report generator
│   ├── comparison.py           # Experiment comparison & diff engine
│   └── metrics.py              # Metric validation utilities
├── docs/                       # Architecture and user documentation
├── tests/                      # Automated validation test suite
└── scripts/                    # Command-line interface utilities
    ├── profile_hardware.py     # Inspect hardware specs & fingerprint
    ├── run_experiment.py       # Execute an experiment
    ├── rerun_experiment.py     # Re-execute an existing experiment
    ├── compare_experiments.py  # Compare two experiment runs
    └── generate_report.py      # Generate markdown report
```

### Architectural Decisions & Rationale
- **Decoupled `runtime/` and `engines/`**: Ensures that when generative backends (e.g. PyTorch, ONNX, TensorRT) are introduced in later phases, the core execution harness, resource monitors, and registries remain 100% stable and untouched.
- **Dedicated `research/experiments/<exp_id>/` Directories**: Ensures that all files generated by an experiment (configs, logs, outputs, reports) reside exclusively in a self-contained folder with no side effects or external file dependencies.
- **Strict Separation of Configs**: Decoupling `ExperimentConfig` from `RuntimeConfig` guarantees that scientific hypotheses can be re-executed across differing hardware clusters without modifying the experiment definition.
